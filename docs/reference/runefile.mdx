---
title: Runefile (server config)
lede: The schema for runed's server configuration file.
---

`runed` is configured via a YAML or TOML file (often called a "runefile"). The default location is `/etc/rune/runefile.{yaml,toml}` — `runed` auto-discovers either format. Override with `runed --config <path>`.

The two formats are equivalent; pick whichever your tooling prefers. TOML is recommended for new deployments because it's stricter about typos and easier to comment.

## Minimal example

```yaml
data_dir: /var/lib/rune

server:
  grpc_address: ":7863"
  http_address: ":7861"
```

## Full example

```yaml
data_dir: /var/lib/rune

server:
  grpc_address: ":7863"
  http_address: ":7861"

log:
  level: info
  format: json

auth:
  allow_remote_admin: false

secret:
  encryption:
    kek:
      source: file              # file | env | generated
      file: /var/lib/rune/kek.b64
  limits:
    max_object_bytes: 1048576
    max_key_name_length: 256

docker:
    registries:
      - name: ghcr-private
        registry: ghcr.io
        auth:
          type: basic
          username: ${GHCR_USER}
          password: ${GHCR_PAT}
      - name: ecr
        registry: "*.dkr.ecr.us-east-1.amazonaws.com"
        auth:
          type: ecr
          region: us-east-1
```

## Sections

### `server`

| Field          | Default          | Notes                                       |
| -------------- | ---------------- | ------------------------------------------- |
| `grpc_address` | `:7863`          | gRPC listen address.                        |
| `http_address` | `:7861`          | REST gateway + [web dashboard](/guides/dashboard) listen address. |
| `require_tls`  | `false`          | With TLS off, bind gRPC to loopback only. Without it, `runed` warns when gRPC serves plaintext on a non-loopback address. Flag: `--grpc-require-tls`. |

#### Server TLS

TLS for the gRPC listener and the dashboard.

| Field                | Default | Notes                                                                 |
| -------------------- | ------- | --------------------------------------------------------------------- |
| `tls.enabled`        | `false` | Serve gRPC and the dashboard over TLS.                                |
| `tls.cert_file`      | —       | Your certificate. Set together with `key_file`.                       |
| `tls.key_file`       | —       | Your private key.                                                     |
| `tls.hosts`          | —       | Extra names and addresses for the self-signed certificate.            |

With `enabled: true` and neither file set, `runed` generates a self-signed P-256 certificate in `<data_dir>/tls/`, valid for loopback, the hostname, the host's interface addresses and `hosts`. The key persists across restarts, and the certificate is re-issued under the same key when it nears expiry or `hosts` changes, so a pinned fingerprint keeps working. The SPKI fingerprint is logged at startup. Renewal is checked only at startup.

If TLS is enabled but the certificate can't be loaded (a missing, unreadable or mismatched file), `runed` refuses to start; it never falls back to plaintext.

<Warning title="The CLI can't connect over TLS yet">

Don't enable `server.tls` on a server you manage with `rune` until the CLI supports it.

</Warning>

<Note title="Unreleased">

On `dev`; ships after v0.0.1-dev.148. Until then `[server.tls]` was parsed and never read, so gRPC was always plaintext.

</Note>

### Top level and `log`

| Field        | Default          | Notes                                       |
| ------------ | ---------------- | ------------------------------------------- |
| `data_dir`   | OS-specific      | BadgerDB + state. A top-level key, not under `server`. Persist across restarts. |
| `log.level`  | `info`           | `debug`, `info`, `warn`, `error`.           |
| `log.format` | `text`           | `text` or `json`.                           |
| `debug`, `pretty` | `false`     | Shorthand for `--debug` / `--pretty` (see [flag overrides](#cli-flag-overrides)). |

### `auth`

| Field                | Default | Notes                                                   |
| -------------------- | ------- | ------------------------------------------------------- |
| `allow_remote_admin` | `false` | If true, `admin/*` works from non-localhost clients.    |

### `ui`

The embedded [web dashboard](/guides/dashboard), served on `server.http_address`.

| Field             | Default | Notes                                                                                     |
| ----------------- | ------- | ----------------------------------------------------------------------------------------- |
| `enabled`         | `true`  | Serve the dashboard at `path`.                                                            |
| `path`            | `/ui`   | Mount point.                                                                              |
| `handoff_enabled` | `true`  | Allow the [`rune ui`](/cli/ui) one-time-code browser sign-in.                            |
| `handoff_ttl`     | `60s`   | Lifetime of a handoff code.                                                               |
| `require_tls`     | `true`  | Without TLS, bind the HTTP listener to loopback only — no plaintext on a public address.  |

### `secret`

Secret encryption and size limits.

| Field                          | Default | Notes                                                    |
| ------------------------------ | ------- | -------------------------------------------------------- |
| `encryption.enabled`           | `true`  | Encrypt secrets at rest.                                 |
| `encryption.kek.source`        | `file`  | How `runed` loads the Key Encryption Key: `file`, `env` or `generated`. |
| `encryption.kek.file`          | `<data_dir>/kek.b64` | Used when `source: file`.                   |
| `limits.max_object_bytes`      | `1048576` | Cap on a whole secret, in bytes.                       |
| `limits.max_key_name_length`   | `256`   | Cap on a key name.                                       |

With `source: env` the key is read from the `RUNE_MASTER_KEY` environment variable; the variable name is fixed. The KEK is 32 bytes, base64-encoded on disk or in the variable. See [Configuration](/operations/configuration#kek-source) for the trade-offs and [Security](/operations/security#kek-lifecycle) for backup and rotation.

### `config`

| Field                          | Default   | Notes                                |
| ------------------------------ | --------- | ------------------------------------ |
| `limits.max_object_bytes`      | `1048576` | Cap on a whole configmap, in bytes.  |
| `limits.max_key_name_length`   | `256`     | Cap on a key name.                   |

Limits are enforced when an object is created or updated; an existing object over a lowered limit stays readable and is rejected on its next write.

<Note title="Unreleased">

On `dev`; ships after v0.0.1-dev.148. Until then the `limits` keys above were ignored and the defaults always applied; only the run-together `maxobjectbytes` / `maxkeynamelength` spellings took effect.

</Note>

### `storage` (volumes)

Controls the persistent-storage subsystem. See the [storage
concept](/concepts/storage) and [storage resources
reference](/reference/storage-resources).

| Field                 | Default                  | Notes                                                                          |
| --------------------- | ------------------------ | ------------------------------------------------------------------------------ |
| `defaultStorageClass` | `local`                  | Cluster default class. Empty string disables the default — `claimTemplate` without `storageClassName` becomes a cast-time error. |
| `drivers.local.localVolumeRoot`      | `/var/lib/rune/volumes` | Root for the `local` driver's managed directory tree. |
| `drivers.local-host.hostPathAllowlist` | `[]`                  | Allowed prefixes for `local-host` `hostPath`. Empty list denies all hostPath usage. `runed --dev-mode` overlays `["~/.rune/volumes"]`. |
| `allowCreateMissing`  | `false`                  | When `true`, honour `local-host` `parameters.createIfMissing: "true"`. `runed --dev-mode` overlays `true`. |
| `preserveOnDelete`    | `false`                  | (`local` driver only.) When `true`, converts `reclaimPolicy: delete` to `retain` — directories survive cascade.  |

```toml
[storage]
defaultStorageClass = "local"
allowCreateMissing = false
preserveOnDelete = false

[storage.drivers.local]
localVolumeRoot = "/var/lib/rune/volumes"

[storage.drivers.local-host]
hostPathAllowlist = ["/mnt/rune", "/var/lib/rune-volumes"]
```

#### `storage.drivers`

Per-driver configuration is keyed by registered driver name. Reserved
for non-credential, non-per-class driver knobs only — credentials and
per-class settings live on `StorageClass.parameters` so they can be
rotated and varied per class. The `do-volume` driver currently takes
no runefile knobs (its API token is sourced from
`StorageClass.parameters.apiToken`, see
[Storage resources](/reference/storage-resources/#do-volume)).

```toml
# Example placeholder — no driver currently requires any of these.
# [storage.drivers.<driver-name>]
# someKnob = "value"
```

### `docker`

| Field                         | Default | Notes                                                              |
| ----------------------------- | ------- | ------------------------------------------------------------------ |
| `api_version`                 | —       | Docker API version to use. Empty means negotiate with the daemon.  |
| `fallback_api_version`        | `1.43`  | Used when negotiation fails.                                       |
| `negotiation_timeout_seconds` | `3`     | How long to wait for version negotiation.                          |
| `log_max_size`                | `10m`   | Container log rotation size; empty disables rotation.              |
| `log_max_file`                | `3`     | Rotated log files to keep; `0` or less omits the limit.            |
| `registries[]`                | —       | Registry credentials; see below.                                   |
| `disable_ambient_registry_auth` | `false` | Skip the ambient credentials described below.                    |

`runed` starts both the Docker and the process runner when it can; a service chooses with its `runtime`. There is no runefile switch to turn one off. The mount permission modes `secret_dir_mode`, `secret_file_mode`, `config_dir_mode` and `config_file_mode` are also accepted (integers).

### docker.registries[]

```yaml
docker:
  registries:
    - name: ghcr-private
      registry: ghcr.io
      auth:
        type: basic
        username: ${GHCR_USER}     # env-expanded at runed start
        password: ${GHCR_PAT}

    - name: ecr
      registry: "*.dkr.ecr.us-east-1.amazonaws.com"
      auth:
        type: ecr
        region: us-east-1
        # AWS credentials inferred from environment / IAM role.
```

| Auth `type`        | Required fields                          | Notes                                              |
| ------------------ | ---------------------------------------- | -------------------------------------------------- |
| `basic`            | `username`, `password`                   | Use for GHCR (PAT as password), Docker Hub, etc.   |
| `token`            | `token`                                  | Bearer token in the `Authorization` header.        |
| `ecr`              | `region`                                 | Pulls a fresh ECR token via the AWS SDK.           |
| `dockerconfigjson` | `dockerconfigjson` (raw JSON)            | Reuse the contents of `~/.docker/config.json`.     |
| `gcp`              | —                                        | Mints a token from the GCE metadata service account at pull time. For `*.pkg.dev` / `gcr.io`. |
| `none`             | —                                        | Explicitly credential-free. Carves a public repository out of a broader credentialed pattern — see below. (`anonymous` is accepted as a synonym.) |

An entry whose `auth` block is missing, has no `type`, or has an
unrecognized `type` is **skipped with a warning** and contributes no
credential — pulls for that pattern go out anonymously.

#### Scoping a `registry` pattern

The `registry` field is matched against the image's **repository
path**, not just its host:

| `registry` pattern              | Matches                                                            |
| ------------------------------- | ------------------------------------------------------------------ |
| `ghcr.io`                       | Every image on the host.                                            |
| `ghcr.io/myorg`                 | Only `ghcr.io/myorg` and repositories beneath it.                   |
| `*.dkr.ecr.us-east-1.amazonaws.com` | Host wildcard.                                                 |

Path comparison is segment-aware: `ghcr.io/myorg` matches
`ghcr.io/myorg/app` but **not** `ghcr.io/myorg-evil/app`.

When more than one entry matches an image, the **most specific one
wins** — deeper path first, then an exact host over a wildcard host,
then the longer pattern — not declaration order. An image no entry
claims gets no configured credential and pulls anonymously.

```yaml
docker:
  registries:
    - name: ghcr-private          # private repos across the whole host
      registry: ghcr.io
      auth:
        fromSecret: ghcr-credentials

    - name: ghcr-public           # ...but THIS path is public
      registry: ghcr.io/myorg/oss
      auth:
        type: none
```

`type: none` is only load-bearing when a **broader** pattern would
otherwise cover the repository. If you simply narrow `registry` to your
private repositories, everything else on the host is already anonymous
without a second entry.

A service can also force a credential-free pull for its own image with
[`imagePullAnonymous: true`](/reference/service-spec#imagepullanonymous),
which needs no runefile change.

<Note title="Ambient credentials still apply to unmatched images">

Beyond `docker.registries[]`, `runed` falls back to ambient credentials —
the GCE metadata service account and the `runed` user's
`~/.docker/config.json` — which carry no pattern and are tried last.
They still apply to images no configured entry matched. Set
`docker.disable_ambient_registry_auth: true` to turn that off.

</Note>

#### Credentials from a Rune Secret (`fromSecret`)

Instead of inlining credentials, an entry can resolve them from an encrypted Rune Secret at runtime — the recommended pattern for production:

```yaml
docker:
  registries:
    - name: ghcr-private
      registry: ghcr.io
      auth:
        fromSecret: ghcr-credentials   # Secret name; runed infers auth type from its keys
```

`runed` infers the auth type from the secret's keys: `username`+`password` → `basic`, `token` → bearer, `.dockerconfigjson` → docker config JSON, `awsAccessKeyId`+`awsSecretAccessKey` (+ optional `awsRegion`) → `ecr`. When `fromSecret` is set, do **not** also set `type` or inline `username`/`password`/`token` — they are ignored.

For first-boot bootstrapping (e.g. from the [Terraform module](https://github.com/runestack/terraform-digitalocean-rune)), the entry can also seed the secret on startup:

| Field        | Notes                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------ |
| `fromSecret` | Name of the Rune Secret to read credentials from at pull time.                                   |
| `bootstrap`  | If `true`, runed creates/updates the secret from `data` on first start (`manage` controls re-apply). |
| `manage`     | `create` (default) or `update`. `update` overwrites the secret on every start; `create` is one-shot. |
| `immutable`  | If `true`, the seeded secret rejects subsequent writes via the API.                              |
| `data`       | Bootstrap seed map (env-expanded against runed's process env). **Ignored at runtime resolution** — only consumed when `bootstrap = true`. |

Manage credentials at runtime with [`rune admin registry`](/cli/admin) — no restart required.
See the [GHCR guide](/guides/ghcr-auth) for a private-image walkthrough.

### `networking`

The cluster networking layer. See [Concepts: Networking](/concepts/networking) for what these knobs do.

| Field           | Default          | Notes                                                                                  |
| --------------- | ---------------- | -------------------------------------------------------------------------------------- |
| `cluster_cidr`  | `10.96.0.0/16`   | Service VIP pool. **Set once at first start** — bootstrapped into the store.            |
| `dev_mode`      | `false`          | Bind service listeners on `127.0.0.1` instead of real VIPs, and shift the ingress to `:8080`/`:8443`. Required on macOS / Docker Desktop. **Implies `node.role: edge`** unless you explicitly set a different role. |

### `telemetry`

| Field           | Default          | Notes                                                                                  |
| --------------- | ---------------- | -------------------------------------------------------------------------------------- |
| `metrics_addr`  | `127.0.0.1:9100` | Prometheus `/metrics` endpoint. Exposes metrics from **all subsystems** (orchestrator, runners, networking, agent, DNS). Set to `""` to disable. |

### `node`

| Field   | Default   | Notes                                                                  |
| ------- | --------- | ---------------------------------------------------------------------- |
| `role`  | `worker`  | `worker` or `edge`. `edge` enables the ingress + ACME subsystems.      |

### `ingress`

Only consulted on edge nodes (`node.role: edge`).

| Field         | Default  | Notes                                  |
| ------------- | -------- | -------------------------------------- |
| `http_addr`   | `:80`    | HTTP listener (also serves ACME challenges). |
| `https_addr`  | `:443`   | HTTPS listener.                        |

### `acme`

Only consulted on edge nodes.

| Field        | Default                                       | Notes                                                                                |
| ------------ | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| `directory`  | `https://acme-v02.api.letsencrypt.org/directory` | ACME endpoint. Override for staging or Pebble in CI.                              |
| `email`      | —                                             | Account contact. Required by Let's Encrypt — issuance fails without it.              |

Issued certificates are persisted in the encrypted state store (one Secret per host under the `system` namespace), so `runed` restarts reuse them rather than re-issuing — important because Let's Encrypt rate-limits to 5 issuances per identifier set per 168 h.

### TOML equivalent

```toml
data_dir = "/var/lib/rune"

[server]
grpc_address = ":7863"
http_address = ":7861"

[networking]
cluster_cidr = "10.96.0.0/16"

[telemetry]
metrics_addr = "127.0.0.1:9100"

[node]
role = "edge"

[ingress]
http_addr  = ":80"
https_addr = ":443"

[acme]
email = "ops@example.com"
```

## CLI flag overrides

Anything in the runefile can be overridden via `runed` flags:

| Flag             | Overrides                |
| ---------------- | ------------------------ |
| `--config`       | path to this file        |
| `--data-dir`     | `data_dir`               |
| `--grpc-addr`    | `server.grpc_address`    |
| `--http-addr`    | `server.http_address`    |
| `--log-level`    | `log.level`              |
| `--log-format`   | `log.format`             |
| `--grpc-require-tls` | `server.require_tls` |
| `--debug`        | shorthand for `--log-level=debug` |
| `--pretty`       | shorthand for `--log-format=text` |
| `--cluster-cidr` | `networking.cluster_cidr`         |
| `--dev-mode`     | `networking.dev_mode`             |
| `--metrics-addr` | `telemetry.metrics_addr`          |
| `--node-role`    | `node.role`                       |
| `--ingress-http-addr`  | `ingress.http_addr`         |
| `--ingress-https-addr` | `ingress.https_addr`        |
| `--acme-directory`     | `acme.directory`            |
| `--acme-email`         | `acme.email`                |

Every key also has a corresponding `RUNE_*` environment variable (e.g. `RUNE_NETWORKING_CLUSTER_CIDR`, `RUNE_TELEMETRY_METRICS_ADDR`, `RUNE_ACME_EMAIL`). Precedence, highest to lowest: **flag &gt; env var &gt; config file &gt; built-in default**.

## Reload behavior

Most fields require a `runed` restart to take effect. Registry credentials managed via `rune admin registry` are hot.
